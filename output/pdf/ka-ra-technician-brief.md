# Ka-ra 光之協定 技術員｜社區救生圈

- 原始碼：brian0731/aieco_mesh，本機基準 53a7e8a。請核對實際 HEAD 與工作區，靠獨立入口／建置設定保留傳播光原有 ID、簽署及資料路徑。
- 交付順序：Android 端到端時間銀行 → 物物交換、信用評分與管理後台 → 光網常駐橋接與斷網演練 → 試點。iOS 使用獨立 bundle ID，待 Apple 工具鏈驗證。
- Flutter 首頁提供找支援、我能幫忙、時間帳、交換及聊天室。免費求助可獨立發出。與真實交易無關的驗收使用測試帳戶與種子資料。
- Nuxt/Nitro 提供管理頁與 /api/v1。交易主帳採 MySQL 8.4，資料表使用 InnoDB 和 `utf8mb4`。分社區及角色授權，每次狀態變更驗證身分及狀態。收錄成員、配對、帳本、物資、交收、申訴與稽核紀錄。以版本化 MySQL migration 管理結構。連線資訊只放後台私有設定。
- 時間銀行依整數分鐘記帳，1 小時等於 60 分鐘，無兌現。服務雙方同意相同時數後，在同一 InnoDB 交易以 `SELECT ... FOR UPDATE` 鎖定配對，再按固定帳戶順序鎖定餘額及寫入相抵分錄。結算設唯一鍵，重試不重複入帳。更正用有理由的相抵分錄。
- 交換流程為刊登、提出交換、接受／保留、雙方交收、完成或申訴。一件物品同時只能保留給一筆交換。交收預設建議選公共地點。
- 沿用相容的 LightMesh 聊天封包與配對目錄，六位碼只用於查找。建置常駐橋接服務、已核准接入名冊與房間映射。只交換獲授權公開房間的聊天，帳本、私訊、交換、定位及 SOS 留在各自系統。先測兩個 relay 雙向互通、去重、停用與復線，之後按實際 App 名冊逐一驗收。
- 無外網時在相通 LAN 上測兩台真機聊天；快取顯示更新時間，交易草稿可保留，恢復連線後再提交或重試。交易完成以後台回覆為準。
- 驗收證據包括原 App 和新 App 同機、Flutter 分析與測試、Nuxt build、實際 MySQL 8.4 的 migration 與整合測試、跨 relay 與 LAN 真機紀錄、本機啟動指令。MySQL 測試覆蓋並行結算、失敗回滾、同一物品競爭保留和重複評分。正式部署、發布、審核試點規則與上架另行排程。

## 信用評分｜v0.2

- Flutter 在交易完成頁提供 1 至 5 星互評，在同社區的成員頁顯示匯總分數及有效評分人數。未滿 3 位不同評分者時顯示「評價資料不足」。成員可查詢自己送出的評價及申訴結果。
- Nuxt API 由登入身分及交易查出社區、評分者與對手，驗證已入帳服務或已完成交換。以後台完成時間起算 7 日，使用伺服器時間。取消、免費求助及未完成交易不具評分資格。交易爭議進行中暫停評價公開與計分。
- MySQL 為「社區、交易種類、交易 ID、評分者」設唯一鍵，並在 API 及資料庫限制整數星數在 1 至 5。每一方只能送出一次。相同送出重試回傳既有結果，內容不同回傳衝突，不覆寫原始評價。
- 雙方都送出或期限屆滿後可公開。公開前，API 不向對手揭露評價內容。匯總取每位對手最近公開且有效的一筆，再對各評分者等權平均，四捨五入至一位小數。以完成時間及交易鍵穩定排序。
- Nuxt 後台提供有權限的社區管理者檢視申訴、恢復或排除評價並即時反映到匯總。稽核保存原因、操作者及時間。成員一般查詢只回傳匯總，信用資料不匯出到光網。舊 App 的聊天室加分不匯入，星等不決定時間帳戶餘額、交易資格或免費求助資格。
- 驗收例：3 位不同對手給 5、4、3 星時顯示 4.0／5（3 位）。同一對手多筆只計最近一筆有效評價。單方評分在期限前對對手保密，期限屆滿才公開。另測第三方送出、同筆並行重送、跨社區查詢、交易爭議移除與恢復，以及新用戶仍可免費求助。
